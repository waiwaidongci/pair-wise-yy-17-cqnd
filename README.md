# 钟乳石洞穴微环境巡测

## 启动

```bash
npm install
npm start
```

默认地址：http://localhost:3912

数据保存在`data/db.json`，后续可以继续增量迭代。

## 深层区离线补传

深层区断网时，巡测人员在「离线补传」页登记：一个**现场单号**同时绑定
**巡测记录**与**样点档案标记**两份内容，先暂存在手机（localStorage），
回到洞口联网后按入队的原始顺序（FIFO）自动续传。本地只暂存，不直接改样点档案。

### 补传规则（服务端裁决）

接口：`POST /api/sync/batches`，请求体：

```json
{
  "ticketNo": "XC-20260929-03",
  "team": "甲队",
  "survey":  { "siteId": "…", "surveyor": "…", "date": "2026-09-29", "temperature": 17.1, "humidity": 90, "co2": 800, "dripRate": 11, "disturbance": "…" },
  "siteMark": { "siteId": "…", "protectedStatus": "重点保护", "note": "…" }
}
```

- **两份一起补传**：缺少任意一份、或两份不指向同一样点，返回 400 且不写库。
- **同号重放沿用首次结果**：现场单号是幂等键。内容指纹一致时直接回放首次结果
  （首次冲突也照旧回放 409），不重复落库。
- **同号内容不同 → 留两份待核对**：首次结果原样保留，异文另存为
  `pending-review` 存档，两份并存，样点档案不改动。
- **同时段别队已关闭 → 整批停写**：同一天另一支队已受理的有效巡测已把样点置为
  「暂停开放」时，本批不写任何巡测、不动样点，返回 409 及冲突来源
  （对方队伍/巡测员/日期/单号），并在 `syncBatches` 留 `conflict` 痕迹。
  本队自己当日的关闭不算冲突。
- **失败不丢、按序续传**：网络失败时队列停在当前位置，本地记录保留，
  恢复联网（或关闭「离线演练」）后继续按原顺序补传。

### 职责划分

- `server/adjudicate.js`：纯判定（校验 / 幂等 / 异文 / 冲突），不做 I/O。
- `server/archive.js`：存档（仅按裁决结果读写 `data/db.json`，
  样点档案只在 `applied` 时才允许变更）。
- `server.js`：HTTP 编排；原有 `/api/:collection` 与动作接口保持不变。
- `public/sync.js` + 「离线补传」页：页面入口独立，原有趋势看板、
  样点/巡测列表与筛选照常。

补传存档集合 `syncBatches` 记录三种结局：`applied`（已受理）、
`pending-review`（同号异文待核对）、`conflict`（整批停写）。
